# ربات مدیریت ارائه‌های درس بینایی کامپیوتر

ربات تلگرام برای برنامه ترم، ثبت‌نام گروه‌های ارائه و یادآوری خصوصی. روی Cloudflare Workers و پایگاه D1 اجرا می‌شود و به سرور جداگانه نیاز ندارد.

هویت هر دانشجو شناسه عددی تلگرام است. نام کاربری فقط برای نمایش در گفتگوی خصوصی نماینده ذخیره می‌شود و در پیام گروه نشان داده نمی‌شود.

## کارهایی که ربات انجام می‌دهد

- نماینده کلاس فصل، تاریخ، ساعت، وضعیت ثبت‌نام و اطلاعات ترم را از داخل تلگرام تنظیم می‌کند.
- دانشجو فقط اگر عضو گروه رسمی درس باشد می‌تواند ثبت‌نام کند.
- هر دانشجو هم‌زمان فقط در یک فصل عضو است.
- هر فصل حداکثر سه دانشجو دارد. با پر شدن ظرفیت، ثبت‌نام همان فصل بسته می‌شود و تیم دوم ساخته نمی‌شود.
- یک پیام برنامه در گروه رسمی ساخته می‌شود و بعد از هر تغییر ویرایش می‌گردد. اگر پاک شده باشد، دوباره ساخته می‌شود.
- در صورت داشتن دسترسی، همان پیام پین می‌شود.
- سه روز قبل و یک روز قبل از ارائه، یادآوری خصوصی ارسال می‌شود. یادآوری صبح روز ارائه فقط وقتی فعال است که نماینده آن را روشن کرده باشد.
- یادآوری تکراری ارسال نمی‌شود. اگر دانشجو ربات را مسدود کند، تلاش دائمی متوقف می‌شود.

تاریخ‌ها در رابط کاربری خورشیدی هستند. در پایگاه داده، روز ارائه به میلادی و ساعت به وقت تهران ذخیره می‌شود. محاسبه یادآوری با اختلاف ثابت `UTC+3:30` انجام می‌شود.

## پیش‌نیاز

- حساب Cloudflare
- Node.js 22 یا جدیدتر
- یک ربات از [@BotFather](https://t.me/BotFather)
- یک گروه تلگرام برای کلاس

ربات باید در گروه عضو و ادمین باشد و اجازه ارسال پیام و پین داشته باشد. Privacy Mode می‌تواند روشن بماند، چون ربات لازم نیست همه پیام‌های گروه را بخواند. برای `getChatMember` باید خودش عضو گروه باشد.

هر دانشجو یک‌بار در گفتگوی خصوصی `/start` را می‌زند. بدون این کار تلگرام اجازه پیام خصوصی نمی‌دهد.

## راه‌اندازی محلی

```bash
npm install
cp .dev.vars.example .dev.vars
npm run db:migrate:local
npm test
npm run dev
```

فایل `.dev.vars` را در گیت قرار ندهید. Wrangler مقدارهای آن را فقط برای اجرای محلی می‌خواند.

## سکرت‌ها و تنظیمات

این مقدارها باید در Cloudflare به‌صورت Secret ذخیره شوند:

| نام | توضیح |
| --- | --- |
| `BOT_TOKEN` | توکن BotFather. هرگز در کد یا کلاینت قرار نمی‌گیرد. |
| `WEBHOOK_SECRET` | رشته ۱۶ تا ۲۵۶ نویسه‌ای از حروف انگلیسی، عدد، `_` و `-`. تلگرام آن را در هدر وب‌هوک می‌فرستد. |
| `ADMIN_TELEGRAM_IDS` | شناسه عددی نماینده‌ها، جدا شده با ویرگول. نام کاربری ملاک دسترسی نیست. |
| `GROUP_CHAT_ID` | شناسه گروه. معمولاً با `-100` شروع می‌شود. نماینده بعداً می‌تواند آن را از منوی تنظیمات عوض کند. |

`TIMEZONE` در `wrangler.jsonc` برابر `Asia/Tehran` است و سکرت نیست.

شناسه عددی خودتان را از [@userinfobot](https://t.me/userinfobot) بگیرید. شناسه گروه را هم می‌توانید با افزودن موقت یک ربات شناسه‌خوان یا از لاگ عضویت ربات ببینید. اگر شناسه گروه را همان اول نمی‌دانید، Secret را با یک مقدار موقت بگذارید و بعد از استقرار، از منوی نماینده اصلاح کنید.

تولید یک مقدار تصادفی برای وب‌هوک:

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

## استقرار

یک‌بار پایگاه را بسازید و شناسه واقعی را جایگزین مقدار نمونه در `wrangler.jsonc` کنید:

```bash
npx wrangler login
npx wrangler d1 create cv-presentation
```

خروجی دستور یک `database_id` دارد. همان را در بخش `d1_databases` فایل `wrangler.jsonc` بنویسید. مقدار `00000000-0000-0000-0000-000000000000` فقط برای توسعه محلی است.

سپس:

```bash
npx wrangler d1 migrations apply cv-presentation --remote
printf '%s' 'TOKEN' | npx wrangler secret put BOT_TOKEN
printf '%s' 'SECRET' | npx wrangler secret put WEBHOOK_SECRET
printf '%s' '123456789' | npx wrangler secret put ADMIN_TELEGRAM_IDS
printf '%s' '-1001234567890' | npx wrangler secret put GROUP_CHAT_ID
npx wrangler deploy
```

بعد از deploy، آدرس Worker شبیه `https://cv-presentation-bot.<subdomain>.workers.dev` است. وب‌هوک را ثبت کنید:

```bash
BOT_TOKEN='TOKEN' \
WEBHOOK_SECRET='SECRET' \
WEBHOOK_URL='https://cv-presentation-bot.<subdomain>.workers.dev' \
npm run webhook:set
```

این دستور فقط مسیر `/webhook` را ثبت می‌کند و توکن را چاپ نمی‌کند.

سلامت سرویس:

```bash
curl https://cv-presentation-bot.<subdomain>.workers.dev/health
```

برای آزمایش زمان‌بند، در حالت محلی:

```bash
curl "http://localhost:8787/__scheduled?cron=*/15+*+*+*+*"
```

`wrangler dev` باید با `--test-scheduled` اجرا شده باشد تا این مسیر فعال باشد:

```bash
npx wrangler dev --test-scheduled
```

## استفاده

دانشجو این دکمه‌ها را می‌بیند:

- مشاهده برنامه ارائه‌ها
- ثبت‌نام برای ارائه
- مشاهده گروه‌های ارائه
- ارائه‌های من
- لغو ثبت‌نام
- راهنما

دستورها: `/start`، `/menu`، `/help`، `/cancel` و `/admin`.

نماینده از `/admin` یا دکمه مدیریت کلاس می‌تواند فصل اضافه کند، عنوان و تاریخ و ساعت را تغییر دهد، ثبت‌نام را باز یا بسته کند، دانشجو را با شناسه عددی اضافه یا حذف کند، ارائه را لغو یا برگزارشده علامت بزند، آمار را ببیند و نام استاد، کتاب، ترم و شناسه گروه را تنظیم کند.

تاریخ را خورشیدی وارد کنید، مثل `۱۴۰۴/۰۸/۲۵`. ساعت را ۲۴ساعته و به وقت تهران وارد کنید، مثل `۱۰:۳۰`.

یادآوری صبح روز ارائه به‌طور پیش‌فرض خاموش است. از تنظیمات ترم روشن می‌شود.

## محدودیت‌های طرح رایگان

این اعداد از مستندات Cloudflare در زمان پیاده‌سازی گرفته شده‌اند و ممکن است تغییر کنند. قبل از ترم آن‌ها را دوباره در مستندات Workers و D1 بررسی کنید.

- Workers رایگان: ۱۰۰هزار درخواست در روز برای همه Workerهای حساب، بازنشانی در نیمه‌شب UTC.
- زمان پردازنده: ۱۰ میلی‌ثانیه برای هر درخواست یا Cron. انتظار برای تلگرام و D1 جزو این زمان نیست. اگر Worker به‌طور مداوم از حد پردازنده بگذرد، Cloudflare اجرا را قطع می‌کند.
- حداکثر ۵۰ subrequest برای هر اجرا، شامل تماس تلگرام و پرس‌وجوی D1. هر batch از D1 یک subrequest است.
- حداکثر ۵ Cron برای هر حساب. این پروژه یکی دارد: هر ۱۵ دقیقه.
- اجرای Cron تا ۱۵ دقیقه دیوار ساعتی وقت دارد، ولی دقت یادآوری در حد ۱۵ دقیقه است، نه ثانیه. اولین اجرای داخل بازه ۲۴ساعته، یادآوری را می‌فرستد.
- D1 رایگان: ۵ میلیون ردیف خوانده‌شده در روز، ۱۰۰هزار ردیف نوشته‌شده در روز، حداکثر ۵۰۰ مگابایت برای هر پایگاه و ۵ گیگابایت برای حساب. برای یک کلاس دانشگاهی این سقف دور است.
- پیام تلگرام حداکثر ۴۰۹۶ نویسه است. برنامه طولانی به چند پیام شکسته می‌شود.
- اگر ربات اجازه پین نداشته باشد، برنامه همچنان ارسال و ویرایش می‌شود.
- پایگاه حتی برای نماینده هم اجازه عضویت در دو فصل یا تیم بیش از سه نفر را نمی‌دهد. برای جابه‌جایی، دانشجو ابتدا حذف و بعد به فصل دیگر اضافه می‌شود.

کرون هر ۱۵ دقیقه حدود ۹۶ درخواست در روز مصرف می‌کند. ثبت‌نام‌های عادی یک کلاس خیلی پایین‌تر از سقف ۱۰۰هزار درخواست می‌مانند.

## آزمایش

```bash
npm test
npm run typecheck
```

آزمایش‌ها شامل هویت تلگرام، عضویت گروه، ظرفیت و ثبت‌نام هم‌زمان برای ظرفیت آخر، لغو ثبت‌نام، متن برنامه، ویرایش و ساخت دوباره پیام گروه، منطقه زمانی تهران، تقویم خورشیدی، و توقف یادآوری بعد از خطای دائمی یا پنج خطای موقت هستند.

## ساختار

- `src/index.ts` ورودی Worker، وب‌هوک و Cron
- `src/bot` منو، دکمه‌ها و جریان نماینده
- `src/services` ثبت‌نام، برنامه گروه، یادآوری و عضویت
- `src/database/schema.ts` مدل Drizzle
- `migrations/0001_init.sql` طرح پایگاه، کلید خارجی، یکتا بودن و سقف سه نفر
- `scripts/set-webhook.mjs` ثبت وب‌هوک

ثبت‌نام با یک `INSERT ... SELECT` انجام می‌شود که ظرفیت و عضویت قبلی را داخل خود دستور بررسی می‌کند. یک trigger هم درج نفر چهارم را رد می‌کند. به‌روزرسانی‌های مربوط به بستن ظرفیت در یک batch تراکنشی اجرا می‌شوند.
